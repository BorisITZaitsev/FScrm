**FitServiceCRM** - учебная CRM-система для автоматизации работы автосервиса Fit Service. Проект реализован как веб-приложение на **ASP.NET Core MVC** с серверными Razor-представлениями, ролевой авторизацией, локальной базой данных SQLite и демонстрационным набором данных для проверки основных бизнес-сценариев.

Система моделирует работу автосервиса с несколькими типами пользователей: системным администратором, руководителем сервиса, мастером-приемщиком и клиентом. В приложении можно управлять клиентами, транспортными средствами, услугами, записями на обслуживание, диагностическими заключениями, заказ-нарядами, согласованиями и уведомлениями.

---

## Что делает проект

Приложение покрывает основной цикл обслуживания клиента в автосервисе:

1. **Регистрация и ведение клиентской базы**  
   Поддерживаются физические лица и юридические лица. Для организаций можно хранить представителей, контактные данные и несколько автомобилей.

2. **Управление транспортными средствами**  
   Для клиента ведется список автомобилей с VIN, госномером, маркой, моделью, годом выпуска, пробегом и цветом. Клиент может редактировать свои автомобили, если по ним нет активных заказ-нарядов.

3. **Каталог услуг автосервиса**  
   В системе есть категории услуг, стоимость, нормативная длительность, тип услуги и рекомендуемый интервал повторного обращения.

4. **Запись на услугу или диагностику**  
   Клиент создает заявку, выбирает один или несколько автомобилей, набор услуг, сервисный центр, дату и комментарий.

5. **Работа с заказ-нарядами**  
   Мастер-приемщик и администратор могут создавать и редактировать заказ-наряды, привязывать услуги, исполнителей, автомобили, работы и диагностические заключения.

6. **Диагностика автомобиля**  
   Мастер-приемщик формирует диагностическое заключение, указывает результат проверки и рекомендации. Клиент может просмотреть заключение и подтвердить ознакомление.

7. **Согласование работ**  
   Заказ-наряд проходит согласование со стороны руководителя сервиса и клиента. Пользователи могут подтвердить работы или отправить запрос на изменение.

8. **История и уведомления**  
   Для заказ-наряда фиксируются изменения статусов, согласования, диагностические события, запросы на изменение и системные уведомления.

9. **Аналитика по завершенным работам**  
   В проекте есть сервис аналитики, который агрегирует завершенные заказ-наряды по месяцам, считает выручку, средний чек и прогнозные показатели для выбранного периода.

## Основные возможности

- Cookie-аутентификация и перенаправление пользователя в интерфейс согласно роли.
- Разделение интерфейсов для администратора, руководителя сервиса, мастера-приемщика и клиента.
- CRUD-операции для пользователей, сотрудников, клиентов, автомобилей, услуг и заказ-нарядов.
- Поддержка клиентов-физлиц и клиентов-организаций.
- Работа с несколькими автомобилями в рамках корпоративного клиента.
- Создание клиентом записей на обслуживание через личный кабинет.
- Ведение заказ-нарядов с услугами, работами, исполнителями, суммами и статусами.
- Создание заказ-наряда на основе диагностического заключения.
- Согласование заказ-нарядов руководителем сервиса и клиентом.
- Запросы на изменение состава работ или сроков.
- Системные уведомления о согласованиях, завершении работ и диагностике.
- История событий по заказ-наряду.
- Автоматическое создание демонстрационной SQLite-базы при первом запуске.
- Возможность запуска локально через `dotnet run` или в контейнере через Docker.

## Запуск проекта

Запустите приложение из папки решения:

```powershell
dotnet run --project .\FitServiceCRM\FitServiceCRM.csproj
```

По умолчанию приложение доступно по адресу:

```text
http://localhost:5253
```

Страница входа:

```text
http://localhost:5253/login
```

При первом запуске приложение:

1. подключается к SQLite-базе `fitservicecrm.db`;
2. создает схему базы данных через `EnsureCreated`;
3. заполняет базу демонстрационными данными из `DemoSeeder`;
4. при обнаружении устаревшей демо-схемы пересоздает локальную базу.

## Запуск через Docker

В проекте есть `Dockerfile` и `compose.yaml`. Для сборки и запуска контейнера можно использовать:

```powershell
docker compose up --build
```

Dockerfile собирает приложение в несколько стадий:

- `build` - восстановление зависимостей и сборка проекта;
- `publish` - публикация приложения;
- `final` - запуск опубликованной сборки на runtime-образе `mcr.microsoft.com/dotnet/aspnet:10.0`.

## Сценарии работы

### Системный администратор

Доступные разделы:

- `Общий вид`;
- `Пользователи`;
- `Сотрудники`;
- `Услуги`;
- `Клиенты`;
- `Заказ-наряды`.

Администратор может:

- создавать и редактировать учетные записи пользователей;
- назначать роли и связывать пользователей с сотрудниками или клиентами;
- управлять сотрудниками автосервиса;
- вести каталог услуг и категорий;
- создавать и редактировать клиентов, представителей и автомобили;
- создавать и редактировать заказ-наряды;
- добавлять работы, услуги, исполнителей и связанные автомобили.

### Руководитель сервиса

Доступные разделы:

- `Общий вид`;
- `Заказ-наряды`;
- `Клиенты`;
- `Сотрудники`;
- `Услуги`.

Руководитель сервиса может:

- просматривать текущие заказ-наряды и связанные карточки;
- фильтровать и сортировать заказы по статусу, периоду и поисковому запросу;
- открывать историю заказ-наряда;
- согласовывать работы;
- отправлять запрос на изменение заказ-наряда;
- просматривать клиентов, автомобили, сотрудников и услуги.

### Мастер-приемщик

Доступные разделы:

- `Общий вид`;
- `Заказ-наряды`;
- `Диагностика`;
- `Клиенты`;
- `Сотрудники`;
- `Услуги`.

Мастер-приемщик может:

- создавать заказ-наряды вручную;
- создавать заказ-наряд на основе диагностического заключения;
- редактировать состав работ, исполнителей и автомобили;
- изменять статусы заказ-нарядов;
- создавать и редактировать диагностические заключения;
- формировать уведомления клиенту о диагностике и согласовании;
- просматривать справочную информацию по клиентам, сотрудникам и услугам.

### Клиент

Доступные разделы:

- `Общий вид`;
- `Запись на услугу`;
- `Профиль`;
- `Транспортные средства`;
- `Заказ-наряды`;
- `Диагностика`.

Клиент может:

- редактировать контактные данные профиля;
- добавлять и редактировать автомобили;
- создавать запись на обслуживание или диагностику;

- просматривать свои заказ-наряды;
- подтверждать заказ-наряд или отправлять запрос на изменение;
- просматривать историю обслуживания;
- просматривать диагностические заключения;

Для клиента-организации дополнительно доступно ведение представителей компании.

## Документация по основным модулям

### `Program.cs`

Файл выполняет стартовую настройку приложения:

- читает строку подключения `DefaultConnection`;
- подключает `AppDbContext` к SQLite;
- настраивает cookie-аутентификацию;
- регистрирует MVC-контроллеры и сервис аналитики;
- создает или обновляет локальную демо-базу;
- подключает статические файлы, маршрутизацию, аутентификацию и авторизацию;
- задает маршруты `/login`, `/logout` и маршрут по умолчанию.

### `AppDbContext.cs`

Контекст базы данных содержит `DbSet` для всех доменных сущностей и настраивает:

- уникальные индексы пользователей, ролей и прав доступа;
- связи один-к-одному, один-ко-многим и многие-ко-многим;
- поведение удаления связанных данных;
- хранение перечислений строками;
- точность денежных полей.

### `AuthController.cs`

Отвечает за вход и выход из системы:

- проверяет логин и пароль;
- запрещает вход неактивным пользователям;
- создает claims с идентификатором, логином, ролью и отображаемым именем;
- перенаправляет пользователя в раздел его роли.

### `AdminController.cs`

Содержит административные сценарии:

- управление учетными записями;
- управление сотрудниками;
- управление клиентами, автомобилями и представителями;
- управление услугами и категориями;
- управление заказ-нарядами и работами.

### `ManagerController.cs`

Реализует интерфейс руководителя сервиса:

- просмотр заказ-нарядов;
- просмотр связанных клиентов, автомобилей, услуг, сотрудников и диагностики;
- согласование заказ-наряда;
- создание запроса на изменение;
- просмотр справочников без редактирования.

### `MasterController.cs`

Реализует рабочее место мастера-приемщика:

- создание и редактирование заказ-нарядов;
- добавление работ и исполнителей;
- изменение статусов;
- создание диагностических заключений;
- создание заказ-наряда из диагностики;
- формирование уведомлений клиенту.

### `ClientPortalController.cs`

Реализует личный кабинет клиента:

- просмотр сводки и уведомлений;
- создание записи на услугу;
- редактирование профиля;
- управление автомобилями;
- просмотр заказ-нарядов;
- согласование работ;
- отправка запросов на изменение;
- просмотр и подтверждение диагностики.

### `WorkOrderSupport.cs`

Содержит вспомогательную бизнес-логику:

- проверку активных заказов по автомобилю;
- сбор истории событий заказ-наряда;
- создание клиентских уведомлений;
- получение отображаемого имени клиента.

### `AnalyticsService.cs`

Аналитический сервис работает с завершенными заказ-нарядами:

- фильтрует данные по услуге, сотруднику и периоду;
- группирует заказы по месяцам;
- считает количество заказов, выручку и средний чек;
- строит прогнозные показатели для следующего периода;
- формирует краткую текстовую интерпретацию для интерфейса.

## Конфигурация

Строка подключения задается в `FitServiceCRM/appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=fitservicecrm.db"
  }
}
```

По умолчанию база создается рядом с запускаемым приложением. Для использования другой SQLite-базы достаточно изменить значение `DefaultConnection`.

Параметры локального запуска находятся в `FitServiceCRM/Properties/launchSettings.json`:

```text
http://localhost:5253
https://localhost:7155
```

## Работа с базой данных

В проекте используется `EnsureCreated`, поэтому отдельные миграции EF Core не требуются для демонстрационного запуска.

Если нужно пересоздать локальную демо-базу вручную:

1. остановите приложение;
2. удалите файл `FitServiceCRM/fitservicecrm.db`;
3. запустите приложение снова.

После повторного запуска база будет создана заново и заполнена seed-данными.
